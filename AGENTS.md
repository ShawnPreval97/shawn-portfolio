## Writing style

- Be specific, clear, confident, and human.
- Avoid generic corporate filler.
- Avoid exaggerated claims.
- Prefer **Problem → Investigation → Solution → Outcome**.
- Do not invent technologies, metrics, employers, or responsibilities.
- Prefer approved copy from `docs/content-plan.md` for homepage sections unless the user supplies new verified content.

## Design and engineering

- Preserve the existing restrained visual identity (warm off-white background, near-black text, serif display treatment, grayscale imagery, light borders, `rounded-sm` geometry).
- Preserve React, Vite, Tailwind, and Vercel deployment.
- Inspect the repository before large edits.
- Make small, reviewable changes.
- Run `npm run build` after implementation changes.
- Do not perform a framework migration.
- Do not add unnecessary dependencies.

## Content source of truth
